## Toast「再次显示后不消失」回归修复
- 现象：图标已变小（新 APK 生效），但 toast 消失后会再次显示并永久不消失。

- 修复（src/utils/toast.ts）：① 改为「仅已超展示时长才兜底关闭」(`tryClearExpired`，按 shownAt+duration 判断)，活跃 toast 不再误杀；② 包装实例 `close` 同步释放 `activeToast` 引用；③ Vant 自带 2s 定时器仍负责正常关闭，仅 pauseTimers 失效的残留由回前台逻辑补关。router.afterEach 的 `toast.clear()` 保留（切路由清上一页 toast 合理）。
- 验证：vue-tsc ✅、vite build ✅、离线包已刷新（index.html 引 index-CQSVrg-k.js；css 仍含 app-toast 30px 图标圈）。需重打 APK 验证真机。

## Toast「不消失 / 先淡出又回来」真正根因（CSS，非 JS）
- 现象：图标已变小，但 toast 消失后再次显示且永不消失。前几轮改 clear() 逻辑是治标。
- 真因：src/styles/toast.scss 根规则 `.van-toast.app-toast { display:flex !important }`。Vant Toast 基于 Popup，隐藏靠 v-show 给元素加「行内 display:none」；`!important` 样式表优先级高于行内样式 → display:none 永远生效不了 → toast 无法隐藏（"不消失"）。先淡出再回来：关时播 van-fade-leave-to(opacity 0) 看似消失，过渡结束 class 移除 opacity 回 1，且 display 被 !important 锁 flex → 又显出来并卡住。
- 修复：去掉根规则 display 的 !important（改 `display:flex;`），让 Vant 的 display:none 能正常生效；其余白底/阴影等 !important 保留。图标圈 .van-toast__icon 的 display:flex!important 属正常、不影响隐藏。已在 SCSS 加警示注释防回归。
- 验证：vite build ✅；离线包 index-B7j_jwsK.css 已验证根规则 display:flex 无 !important，仅图标圈保留 !important。
- 结论：混合架构里覆盖第三方组件(AntD/Vant等)基于 v-show/display:none 隐藏的浮层时，display 类属性绝不可加 !important。
