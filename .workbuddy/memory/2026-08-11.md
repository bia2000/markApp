## 关键坑：真机看不到 H5 新改动 = 离线包没刷新
用户反馈真机上按钮（shortcut "添加到桌面"）不显示，逐层排查定位：

1. **H5 平台判断正常**：`isAndroid` 由 `device.getPlatform` 决定，桥在 `BaseWebFragment.onCreateView` 的 `addJavascriptInterface` 注入（早于 `loadUrl`），桥名 `NativeBridge` 与 H5 `BRIDGE_GLOBAL_NAME`(无 .env→回落 NativeBridge) 一致。不是检测问题。
2. **真机只加载打包离线包**：`BaseWebFragment.hasBundledOffline()` 只要 `assets/offline` 非空即 true → 永远走 `file:///android_asset/offline`，**不会**回退开发服务器。所以 H5 源码改了但离线包不重打，真机永远跑旧页面。
3. **验证技巧**：在 `native/android` 整个目录 grep 按钮文案（如"添加到桌面"），搜不到即离线包陈旧。
4. **构建被安全删除拦截**：本机 `vite build` 清空 `dist` 时触发 WorkBuddy 的 safe-delete 接管（rmSync→丢回收站）失败而 build 挂。绕过：`vite build --outDir dist_build`（新目录不触发 emptyDir）。
5. **刷新离线包流程**：托管 node 跑 `vite build --outDir dist_build` → `cp -r h5/dist_build/. native/android/app/src/main/assets/offline/` → 重新打包 APK 安装真机才生效。

**结论**：任何 H5 改动在真机生效 = 重 build H5 + 覆盖 assets/offline + 重打 APK。浏览器预览只能看 UI 布局，不能验证原生桥相关功能。

## MIUI 钉桌快捷方式失败（add shortcut failed, has no permission）
真机（小米/MIUI）点「添加到桌面」弹确认框但桌面无图标，log 关键行：`com.miui.home E add shortcut failed, com.example.hybrid has no permission`。

- 根因：MIUI 现代 `ShortcutManager.requestPinShortcut` 确认框能弹、落盘必失败（已知坑）；落盘时校验 MIUI 专用权限 `com.miui.home.permission.INSTALL_SHORTCUT`（manifest 里只声明了标准 `com.android.launcher.permission.INSTALL_SHORTCUT`，没声明 MIUI 这个）。
- 修复：`ShortcutPlugin.requestPin` 检测到 MIUI（`ro.miui.ui.version.name` 或 brand=xiaomi）就改走老式 `INSTALL_SHORTCUT` 广播；manifest 补 `com.miui.home.permission.INSTALL_SHORTCUT`；H5 `onAddToHome` 按 `pinned` 真实结果提示，失败时引导去系统设置开「桌面快捷方式」权限。
- 用户必须**重打 APK**（原生+manifest 改动）并在真机**干净重装**（uninstall 再装，确保 MIUI 授予新权限）；若仍失败去 MIUI 设置→应用设置→权限管理→本应用→桌面快捷方式→允许。
- 构建坑复现：vite 清空已存在的 outDir 会触发本机 safe-delete 拦截导致 build 挂，必须每次用**全新 outDir**（如 dist_build2）再 `cp -r` 进 assets/offline。

## MIUI 钉桌路由纠偏（重要）
用户已授予「桌面快捷方式」权限、且补了 `com.miui.home.permission.INSTALL_SHORTCUT` 后仍失败，新版 log 只剩 `GPUAUX Null anb`（MIUI GPU 诊断噪声，无关），旧 `add shortcut failed` 已消失——证明权限生效、广播已发出、但桌面无反应。

- **方向纠正**：上一版把 MIUI 强制改走老式 `INSTALL_SHORTCUT` 广播是误判。证据：最早 log 显示现代 API 实际**弹出了确认框**（`AddItemActivity`/`CONFIRM_PIN_SHORTCUT`），失败发生在"确认后落盘"且原因是缺权限——也就是说现代 API 本就被 MIUI 正常受理，只是当时缺权限。MIUI 12+ 授权后对老广播反而可能静默忽略。
- 修复：`ShortcutPlugin.requestPin` **去掉 MIUI 特判，统一优先 `ShortcutManagerCompat.requestPinShortcut`（现代 API）**，广播仅作 API<26 兜底；删除 `isMiui()`。图标沿用 App 本身的 `@android:drawable/sym_def_app_icon`（项目无自定义 mipmap）。
- 纯原生改动，**无需刷新离线包**，重打 APK 即可。
- 教训：MIUI 钉桌失败要先查权限/确认框是否弹出，别急着改路由；现代 API 在权限齐备时是最稳路径。

## 桌面组件（App Widget）实现（用户要的是真·组件，不是快捷方式）
用户确认 shortcut 跑通后，要求改成「桌面组件」：展示事项列表、点事项行即记录一次（复用 tapItem）。

### 架构要点
- Android App Widget 用 `RemoteViews`，**不能渲染 H5/WebView**，故组件显示的数据必须由 H5 经桥同步到原生存储。
- H5 改数据时把「事项+今日次数」推到原生 `SharedPreferences`（`hybrid_storage`，与 StoragePlugin 共用），App Widget 跑在 App 自己进程内，读这份 SP 即可渲染，无跨进程坑。
- 链路：H5 `useWidget`（数据变更 watch → `widget.sync`）→ `WidgetPlugin` 写 `widget:payload` + 广播 `APPWIDGET_UPDATE` + `notifyAppWidgetViewDataChanged` → `TodoWidgetProvider`(RemoteViews 头+ListView) + `TodoWidgetService`/`TodoWidgetFactory`(读 payload 渲染行) → 点行 `fillInIntent` 带 item_id → `MainActivity`(RECORD_ITEM 意图) → dispatch `record_item` → H5 `todo.tapItem(id)`，自动重新同步组件。

### 新增/改动文件
- 原生 `widget/TodoWidgetProvider.kt` / `TodoWidgetService.kt` / `TodoWidgetFactory.kt`，`bridge/plugins/WidgetPlugin.kt`（`widget` 命名空间：`sync`/`getPendingRecord`，常量 `WIDGET_PAYLOAD_KEY`/`RECORD_ITEM_ACTION`/`EXTRA_ITEM_ID`/`RecordState`）。
- `res/xml/todo_widget_info.xml`、`res/layout/widget_todo.xml`(头部+ListView+empty)、`res/layout/widget_todo_row.xml`(标题+次数)。
- `AndroidManifest.xml`：WidgetProvider receiver（`exported="true"`，接收系统 APPWIDGET_UPDATE）+ TodoWidgetService（`BIND_REMOTEVIEWS`）。
- `JSBridge.kt`：注册 WidgetPlugin；`dispatchEvent` 改返回 Boolean（有无 WebView 接收，用于决定冷启动兜底）。
- `MainActivity.kt`：`handleRecordIntent` 解析 RECORD_ITEM_ACTION，仅当未送达 H5 时置 `RecordState.pendingItemId`（防热启动+重建导致的双记）。
- `bridge-protocol`：加 `WidgetItem`/`WidgetPayload`/`widget.sync`/`widget.getPendingRecord`/`record_item` 事件。
- H5 `composables/useWidget.ts`（新建）+ `home/index.vue` 接入。

### 本轮发现的编译/逻辑 Bug（重打 APK 前已修）
1. `useWidget.ts` 误用 `todo.items.value` 等——Pinia setup store 的 `todo.items` 已自动解包，`.value` 是 undefined，会推送空/报错。**已改为 `todo.items`**。
2. 原生 4 处缺 import 跨包常量导致编译失败：`WidgetPlugin` 缺 `import com.example.hybrid.R`（`R.id.widget_list`）；`TodoWidgetProvider` 缺 `WIDGET_PAYLOAD_KEY`+`JSONObject`；`TodoWidgetFactory` 缺 `WIDGET_PAYLOAD_KEY`。**已补**。
3. WidgetProvider receiver 原 `exported="false"` → 在 Android 12+/MIUI 上收不到系统 APPWIDGET_UPDATE 广播、添加列表异常。**已改 `exported="true"`**。
4. record 双记隐患：hot-start 既 dispatch 又置 pending，Fragment 重建重跑 `getPendingRecord` 会记两次。**已让 `dispatchEvent` 返回是否送达，仅未送达才留 pending**。

### 组件点击「记一次」没统计（事件丢失，已修）
- 现象：点桌面组件里的事项行 → 打开 App，但统计没 +1。
- 根因：原生 `dispatchEvent` 的「是否送达」判定只看 `webViews`（WebView 实例注册表），**不判断 H5 的 `_recvEvent` 监听器是否挂载**。冷启动/白屏期 H5 还没 ready，事件被 JS 端 `&&` 短路丢弃，原生却误判送达、不置 pending，记录丢失。
- 修复（H5 ready 握手 + 事件队列）：
  1. 新增 `AppReadyPlugin`（namespace=`app`，处理 `ready`）；JSBridge 增加 `h5Ready` 标志 + `pendingEvents` 队列 + `markH5Ready()`（冲刷队列）。`dispatchEvent` 在 H5 未就绪时排队、就绪后冲刷。
  2. H5 `useWidget.onMounted` **先同步注册 `record_item` 监听**，再 `await call('app.ready')` 通知原生——保证冲刷时监听已挂载，事件不丢。
  3. `bridge-protocol` 登记 `app.ready`；`bridge/index.ts` mock 加分支。
  4. `MainActivity.handleRecordIntent` 简化为只 `dispatchEvent`（不再依赖 pending 兜底，避免双记）；`RecordState` 仅 `WidgetPlugin.getPendingRecord` 引用（恒 null，无害）。

- 教训：**原生派发事件给 H5 不能只看 WebView 实例是否存在**，必须以 H5 显式 ready 握手为准；冷启动事件必须排队而非丢弃。

## 桌面组件改为「纯原生记账，不打开 App」（最终实现，用户要的"点了不打开、桌面直接 +1"）
用户反馈上一版（事件握手链路）真机仍"点了没记上"，明确要组件单独做原生记事。改为原生直接落库：

### 根因补充（关键！）
- 组件列表行用 `setOnClickFillInIntent` 逐行回填 `EXTRA_ITEM_ID`，再 `setPendingIntentTemplate`。
- **Android 12+(API31+) 上，被 fillIn 的 PendingIntent 必须用 `FLAG_MUTABLE`**，否则点击时回填的 extra 被剥离 → `itemId` 为 null → 旧实现（`handleRecordIntent` 拿到 null 不 dispatch）表现为"打开 App 但没统计"。这很可能就是一直"点了没记上"的真凶。模板 PendingIntent 已改 `mutableFlags()`（API>=S 用 `FLAG_MUTABLE`，否则 0）。

### 新架构（原生侧独立完成 +1，共享存储回写 H5）
- H5 记录存在 **WebView 自己的 localStorage**（`notepad:records`），**原生读不到**；原生与 H5 唯一共享通道是 `hybrid_storage` 里的 `widget:payload`（H5 经 `widget.sync` 写入）。
- 新增原生 `widget/WidgetRecordReceiver.kt`（BroadcastReceiver，exported=true，收 `RECORD_ITEM_ACTION`）：收到点击 → 追加一条记录到 `hybrid_storage` 的 `widget:records`（新 key，与 H5 localStorage 解耦）→ 重算今日次数回写 `widget:payload` → 广播 `APPWIDGET_UPDATE` 刷新组件。**全程不启动 Activity，实现"点了不打开 App、桌面直接 +1"。**
- `TodoWidgetProvider.updateWidget`：列表项点击 PendingIntent 模板从 `getActivity(MainActivity)` 改为 `getBroadcast(WidgetRecordReceiver)`，并改用 `mutableFlags()`。
- `MainActivity.kt`：删除 `handleRecordIntent`（及其 `RECORD_ITEM_ACTION`/`EXTRA_ITEM_ID`/`JSONObject` 引用）；新增 `onResume()` → 首页 `resyncData()`，让 App 回到前台时拉取原生记录合并。
- `WidgetPlugin.kt`：新增常量 `WIDGET_RECORDS_KEY="widget:records"`。
- `AndroidManifest.xml`：注册 `WidgetRecordReceiver`（exported=true，intent-filter `com.example.hybrid.action.RECORD_ITEM`）。
- H5 `stores/todo.ts`：新增 `mergeRecords(incoming)`（按 id 去重合并）。
- H5 `composables/useWidget.ts`：移除 `record_item` 监听与 `getPendingRecord`；新增 `pullNativeRecords`（读 `storage.local.get 'widget:records'` 并 `mergeRecords`）+ 导出 `resyncWidget()`（合并+重推 payload）。`onMounted` 改为先 `pullNativeRecords`→`pushPayload`→`app.ready`，再 watch 自动 sync。
- H5 `main.ts`：`__todoResync` 扩展为 `todo.rehydrate()+summary.rehydrate()+void resyncWidget()`，使切 Tab / 回前台都合并原生记录。

### 同步语义
- 组件点击：原生写 `widget:records`（权威，跨 App 打开持久）+ 立即刷新 `widget:payload`（桌面 +1）。
- App 打开/回前台：H5 经 `resyncWidget` 把 `widget:records` 合并进 localStorage `notepad:records`（按 id 去重，不重复），统计页/总结页自动正确；随后 `pushPayload` 把含原生记录的今日次数回写 `widget:payload`，保持一致。
- `widget:records` 不清空（靠 id 去重防重复），长期累加，对个人记事本可接受；如需可让 H5 合并后清。
