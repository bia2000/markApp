## 迭代：原生 TabBar 真正改为 2 tab（记事项/统计）并修复路由
- 用户要求：「原生的 tabbar 也改了，需要把统计的 tabbar 显示出来」。上一轮只改了 H5（原生环境不自绘 + 注册协议），但原生壳自己的 TabBar 仍硬编码 4 个旧 tab（首页/分类/消息/我的），且 iOS 根本没把 routePath 用上。
- **iOS 改动**：
  - `native/ios/.../Shell/MainTabBarController.swift`：tab 从 4 个改为 2 个（记事项→/home 用 home 图标，统计→/stats 用 grid 图标）。
  - `native/ios/.../WebView/HybridWebViewController.swift`：`loadEntry()` 原来**完全忽略 routePath**（所有 tab 只加载 index.html→被重定向到 /home，统计 tab 形同虚设）。改为把 routePath 以 **hash** 拼到入口 URL：`entryURL()#/routePath`（离线 file:// 与远程均适用）。
  - `MainTabBarController` 的 `didSelect`：切换 tab 后调用 `top.webView.evaluateJavaScript("window.__todoResync && window.__todoResync()")` 触发 H5 重新读取数据。
- **Android 改动**：
  - 新建 `native/android/.../shell/tab/StatsWebFragment.kt`（routePath=/stats）。
  - `MainActivity.kt`：fragments 改为 [HomeWebFragment, StatsWebFragment]，titles ["记事项","统计"]，底部导航监听 tab_home→0 / tab_stats→1；切换后 `evaluateJavascript("window.__todoResync && window.__todoResync()", null)` 触发同步。
  - `BaseWebFragment.kt`：`loadEntry()` 由 `cleanBase+routePath` 改为 `cleanBase#routePath`（hash 模式）。
  - `res/menu/menu_bottom_nav.xml`：改为 2 项（tab_home 记事项、tab_stats 统计）。
- **H5 路由切 hash 模式**：`h5/src/router/index.ts` 由 `createWebHistory()` 改为 `createWebHashHistory()`。原因：history 模式在离线包 `file://` 与多 WebView 各加载独立 URL 场景下无法稳定路由，hash 最稳。
- **跨 WebView 数据同步（关键）**：每个原生 tab 是独立 WebView，共享 localStorage 但各自 Pinia 内存态独立，切 tab 时另一边会显示旧数据。修复：`stores/todo.ts` 新增 `rehydrate()`（从 storage 重新读取 items/records）；`main.ts` 在 `visibilitychange`/`pageshow` 时调用，并暴露 `window.__todoResync`；原生切 tab 时主动 evaluateJavaScript 触发，保证统计页看到最新结果。
- 构建/`nav.setTabBar`：本次原生改为**硬编码 2 tab**，此前加的 `nav.setTabBar` 协议+helper 未被原生消费（无害，留作扩展）。`main.ts` 里对原生环境的 `setTabBar()` 调用已移除（仅保留 `app-native` class 标记）。
- 验证：H5 `npm run build` 通过并 preview（200），新包含 `__todoResync`。**原生侧无法在本机编译**（无 Xcode/Android SDK），仅做源码逻辑改动，需用户在原生工程内编译验证。
- **Android 编译报错修复**：`MainActivity.kt` 直接访问 `BaseWebFragment.webView` 报 `Cannot access 'webView': it is protected`。原因：Kotlin 的 `protected` 仅子类可见（不同于 Java 同包可访问）。修复：在 `BaseWebFragment` 新增 `public fun resyncData()`（内部 `webView.evaluateJavascript("window.__todoResync && window.__todoResync()", null)`，`::webView.isInitialized` 守卫），`MainActivity` 改为 `(fragments[pos] as? BaseWebFragment)?.resyncData()`。
- **禁用 Android ViewPager 左右滑动切页**：用户反馈左滑会切换页面。原因：`androidx.viewpager.widget.ViewPager` 默认拦截水平滑动翻页。修复：新增 `native/android/.../shell/NonSwipeableViewPager.kt`（`onInterceptTouchEvent`/`onTouchEvent` 均 return false，滑动透传给内部 WebView），`activity_main.xml` 改用该类，`MainActivity` 的 `viewPager` 类型改为 `NonSwipeableViewPager`（并移除 `androidx.viewpager.widget.ViewPager` 导入）；点底部 TabBar 仍能通过 `setCurrentItem` 切换。iOS `UITabBarController` 默认无滑动切 tab，无需改。

## APK 打包相关
- **H5 离线包打入 APK（关键）**：原生壳 `OfflinePackage` 默认从 `filesDir/offline` 或回退到 `http://192.168.121.34:5173/`（电脑 dev 服务器）读页面；不打包则 APK 装真机会连电脑 dev 地址、打不开。处理：
  - `npm run build` 出的 `h5/dist` 拷贝到 `native/android/app/src/main/assets/offline/`（vite `base:'./'` 已是相对路径，适配 `file:///android_asset/offline/`）。
  - `BaseWebFragment.loadEntry()` 改为：若 `assets/offline` 存在则加载 `file:///android_asset/offline#routePath`，否则回退 dev 服务器（`requireContext().assets.list("offline")` 判断）+ `hasBundledOffline()` 辅助。
  - 选 `android_asset` 方案而非 `filesDir` 方案：避开 file:// 跨源加载 JS/CSS 的 `allowFileAccessFromFileURLs` 限制。
- **本沙箱命令行无法直接出 APK（环境限制）**：Gradle 8.5 已缓存，但本命令行（Git Bash/PowerShell）里 **fresh Gradle JVM 无法加载 `native-platform.dll`**（`Could not initialize native services / Failed to load native library 'native-platform.dll'`）。一次 daemon 模式构建（kw81pb）能编译通过（资源/清单/Kotlin/assets 全过，仅败在临时锁 `signing-config-versions.json` AccessDenied），因它复用了用户 AS 先前启动、已加载原生库的守护进程；杀掉守护进程后全新 JVM 即加载不了。**结论**：项目能编译，APK 需用户在 Android Studio 出。全局 `~/.gradle/native` 未被真正破坏（dll 仍在）。
  - 坑：`gradlew`(sh) 本机 CRLF，Git Bash 报错；直接 `gradle`(sh) 调 `cygpath` 缺失；可用 `gradle.bat`（Windows 原生）经 PowerShell，daemon + `--offline`。
- **离线包加载 ERR_FILE_NOT_FOUND 修复（2026-08-04）**：`BaseWebFragment.loadEntry()` 原拼接 `file:///android_asset/offline#/routePath`，指向**目录**；Android WebView 在 file:// 下不会自动找 index.html，报 `net::ERR_FILE_NOT_FOUND`（URL 显示 `file:///android_asset/offline#/home`）。修复：改为显式 `file:///android_asset/offline/index.html#/routePath`（目录后补 `/index.html`）。**改完只需用户在 Android Studio 重新 Build APK**，H5 无需重新 build（assets/offline 已是最新）。根因：file:// 必须经具体文件名，hash 拼在文件名之后作客户端路由。
- **加载遮罩卡死修复（2026-08-04）**：用户反馈重打后「卡在正在加载」。根因：`loadingOverlay` 隐藏只挂在 `WebChromeClient.onProgressChanged` 到 100，加载失败（ERR_FILE_NOT_FOUND 旧包）时进度到不了 100 而永久挂遮罩。修复：`BaseWebFragment` 的 `webViewClient`（继承 `OfflinePackageClient`）重写 `onPageFinished` 隐藏 overlay，并加 `onReceivedError` 两个重载兜底隐藏；`onProgressChanged` 保留为辅助。结论：遮罩隐藏逻辑必须放 `onPageFinished`/`onReceivedError`，不能只靠进度。
  - 踩坑：`BaseWebFragment` 用 `object : OfflinePackageClient()` 匿名继承报错 `This type is final, so it cannot be inherited from`（Kotlin 类默认 final）。修复：将 `OfflinePackage.kt` 中 `class OfflinePackageClient` 改为 `open class OfflinePackageClient`（WebViewClient 子类，其余实例化处不受影响，离线拦截逻辑保留）。
- **「卡在正在加载中」真因（file:// 离线包 ES module 被拦截，2026-08-04）**：用户重打 APK 后仍卡「正在加载」。排查发现页面里**有两层**「正在加载」：① 原生遮罩 `fragment_web.xml`（文字"正在加载"，onPageFinished 隐藏）；② H5 启动页 `#app-splash`（`h5/index.html` 内联，文字"正在加载"，由 `main.ts` 在 `app.mount` 后 `splash.remove()` 移除）。原生 `AppPlugin` 的 namespace 实为 `"device"`，`device.getPlatform` 原生能正确处理，H5 侧 `appStore.init()` 不挂。真因：打包产物 `assets/offline/index.html` 用 `<script type="module" crossorigin src="./assets/index-xxx.js">`，**Android WebView 默认 `allowFileAccessFromFileURLs=false`，按 file:// 同源策略拦截子目录 JS/CSS 模块**，导致 ES module 永不加载、`main.ts` 不执行、`#app-splash` 永不移除；原生 `onPageFinished` 只认 HTML 加载完照样隐藏原生遮罩，于是露出 H5 那层「正在加载」。修复：`BaseWebFragment.onCreateView` 开启 `webView.settings.allowFileAccessFromFileURLs = true` + `allowUniversalAccessFromFileURLs = true`；并给原生遮罩加 4s `postDelayed` 兜底强制隐藏。结论：**Vite/Vue 打包进安卓 WebView 必须开这两个开关**，否则离线包 JS 全挂。
- **软键盘弹出时原生 TabBar 悬浮键盘上方（2026-08-04）**：`MainActivity` 未设 `android:windowSoftInputMode`，`BottomNavigationView` 在 `LinearLayout` 里平铺固定底部，键盘弹出（adjustPan/adjustResize 默认行为）时随窗口上推、悬浮输入法之上。修复：`MainActivity` 新增 `setupKeyboardListener()`，用 `ViewTreeObserver.OnGlobalLayoutListener` 检测内容帧 `getWindowVisibleDisplayFrame` 与 `rootView.height` 差值（>屏幕15% 视为键盘），键盘显示时 `bottomNav.visibility = GONE`（释放底部空间，WebView 撑满），收起恢复 `VISIBLE`。只改 `MainActivity.kt`，H5/离线包无需重打。

## 迭代：新增导出/导入备份功能（2026-08-04）
- 用户需求：「加个导出/导入备份吧」。
- **设计原则：零原生改动**。复用既有能力：①浏览器预览用 Blob 下载 `.json`；②原生壳内导出走现有 `share` 桥（`SharePlugin` 双端均已实现，分享纯文本→系统分享面板，用户可「存储到文件」留存）；③导入用 `<input type="file" accept=".json">`（WebView 内会唤起系统文档选择器，双端通用）+ 一个粘贴 JSON 的 textarea 作为兜底（覆盖 iOS 系统分享回调链路不回传、无法确认的场景）。
- **store 改动** `h5/src/stores/todo.ts`：新增 `BackupData` 接口（version/exportedAt/items/records）；`exportData()` 返回完整备份对象；`importData(raw)` 做基础结构校验（items/records 须为数组）后**覆盖式**写入并持久化，返回 {items,records} 数量。
